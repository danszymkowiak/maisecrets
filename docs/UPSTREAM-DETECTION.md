# Detection improvements in this fork, ranked for upstream

For the maintainers of `Mcpgate-de/maisecrets`. This fork started from v0.6.11 (2026-10-10). Its
detection changes were measured with a rule benchmark (`bench/`, `docs/BENCHMARK.md`). This page
lists the changes upstream could take, with the most gain for the least work first. The fork's other
work (the `redact` tool, the vault's key in the Secret Service, personal terms) is left out: it is
not detection.

## How it was measured

Three detectors ran on the same labelled data with the same bench, on 2026-10-14:
upstream v0.6.11 (the fork point, run 20261014-003150), upstream v0.6.15 (upstream today, run
20261014-003838) and this fork (run 20261014-004406). The bench can measure any checkout:
`MAISECRETS_BENCH_DETECTOR=<path> uv run --project bench python bench/run.py`.

The datasets, about 215,000 samples counted here:

| dataset | what | licence |
|---|---|---|
| CredData (Samsung) | source files with labelled credentials | Apache-2.0 tooling, each file its project's licence |
| Gretel synthetic_pii_finance_multilingual | finance documents in 7 languages | Apache-2.0 |
| NVIDIA Nemotron-PII | 100,000 documents of 50+ industries | CC BY 4.0, attribution: NVIDIA |
| Mendeley synthetic financial documents (doi 10.17632/tzrjx692jy.1) | auditor reports, tax filings | CC BY 4.0, attribution: the dataset's authors |
| PIILO (The Learning Agency Lab, the data of Kaggle's PII Data Detection) | 6,800 real student essays | CC BY 4.0, attribution: The Learning Agency Lab |
| findocs (generated by this fork) | Swiss and German salary, tax and bank documents | ours |
| synthetic tool output (generated by this fork) | 3,000 terminal outputs, a guard | ours |

One more dataset ran on this machine and is left out of every number here: its licence allows
academic, non-commercial use only.

Totals without it (correct finds / false alarms):

| | v0.6.11 | v0.6.15 | fork |
|---|---|---|---|
| correct finds | 256,907 | 257,094 | 267,213 |
| false alarms | 9,105 | 9,117 | 8,146 |

Two caveats. findocs was written by this fork for the documents it targets, so its gain (score
78.2% to 100%) is partly by design. And the fork chose its changes on the bench's dev half of each
dataset; the numbers here are over both halves.

## The list

Each row: what changes, its measured effect against upstream v0.6.15 (rule or type level, without the
restricted dataset), the effort to port, and the fork's commits.

### 1. Data-only false-alarm cuts

Changes to a table or a validator, each a few lines. About 630 fewer false alarms in total, for 4 finds
(the NPI and Swedish organisation number rules lost 4 labelled finds; not yet looked at one by one).

| change | false alarms | commits |
|---|---|---|
| uk-postcode in `PRESIDIO_SKIP`: a postcode alone identifies no one, every hit was a false alarm | -263 | 8842bb8 |
| it-fiscal-code checks its check letter (Presidio's own algorithm) | -153 | 94c1d97 |
| de-vat-id, bare `DE` + 9 digits: needs a VAT word; its hits were FIX and XML identifiers that pass the checksum | -60 | 809a0a9 |
| es-nif, us-npi, se-organisationsnummer, uk-vehicle-registration: Presidio's checksums ported, context word kept | -120 | d72ea2b |
| de-handelsregister in `PRESIDIO_SKIP`: a company's register number, public, not personal data | -32 | 809a0a9 |

### 2. A US phone number written `(NXX) NXX-XXXX`

One regex in the `us` region (area code and exchange 2-9, no reserved middle 9). PHONE +2,892 finds,
+42 false alarms, most of them real-looking numbers the datasets left unlabelled. Commit 8295dc8.

### 3. IBANs in bank exports and other spellings

An IBAN after an MT940 subfield code (`:86:…?31DE89…?32`, the counterparty in a bank statement
export), in lower case (then it must have its country's length: a lowercase hex digest passes mod
97 one time in 97), and with hyphens between its groups. IBAN +606 finds, no new false alarm.
Commits 8c943ee, b2ca04c.

### 4. Password labels that open a sentence

Small checks on the detect-secrets keyword rules: an identifier constant (`UPPER_SNAKE`) or a time
or ratio after a label is no value; `passes:`, `passed:` and `passing:` are no password label; a
number of seconds at the end of a sentence is no password; a keyword and a colon that open a
sentence in a markdown table cell are no value. 477 fewer false alarms (ds-keyword-equal-signs
-373, ds-keyword-colon -104). Commits f2c9ee2, 9dae6fa, 24e0162, 3355cb8.

### 5. Card numbers

A number that passes Luhn is reported without a context word, except a published test number
(`4111 1111 1111 1111`, Stripe's `4242…`) without a card word nearby, and a number right after a
`+` (a phone number such as `+4915112345678` passes Luhn too). Card words in the label languages
count (Karte, Kreditkarte, carte, carta, tarjeta, …). CARD +657 finds, +53 false alarms.
Commits 795b411, d5807ea.

### 6. generic-api-key: one entropy floor per alphabet

Raw entropy rises with the alphabet, so one 3.5 treats a hex value and a base64 one alike. Floors
chosen on the dev half: hex 3.449, base32 3.584, base62 3.322, base64 3.252, base64url 3.426,
printable 3.594. Judged alone: about +110 secrets, -10 false alarms, mostly on CredData. A
function of 20 lines. Commit 795b411.

### 7. A Swiss region (medium effort)

`ch`: the AHV/AVS number (EAN-13 checksum; the dotted form stands alone, the bare 13 digits need a
context word) and the company UID (mod 11). 6,000 of 6,000 on findocs, no false alarm on any other
dataset. A new region and two validators. Commit d4eb28b.

### 8. A normaliser before the shape rules (larger)

The text is cleaned of terminal and encoding disguises (ANSI codes, carriage returns, invisible
characters, line gutters, HTML entities, full-width letters), base64 and hex runs are decoded, and
tokens wrapped across lines are joined; a hit in the cleaned copy redacts the original span through
an offset map. On the bench: CredData +16 secrets, Nemotron +4. Its main value is against disguised
values: base64 perturbation recall 63.8% to 71.1%. About 390 lines in three modules with their
caps (bytes, candidates, a time slice). Commits ef1ffee, fb9124f, a3fbdb3 and the perf fixes after them.

### Already in upstream, or to take the other way

- **Betterleaks:** upstream switched to Betterleaks on its own (baf8e64). The fork's rule filters
  as data (a823e8a, b5b2cbd) are not needed.
- **Upstream's password fixes** (32a729c, d159fb7: `--password`, `mysql -p`, Redis AUTH, `.netrc`,
  "my password is …", JSON inside a string) find about 170 more generic secrets than the fork.
  The fork has not merged them yet; the two sets do not conflict.

## The data needs cleaning before it can judge a rule

A rule change judged on raw labels is judged partly on errors. The bench checks every labelled
value before scoring (`bench/maisecrets_bench/validgold.py`, `bench/audit.py`, `docs/BENCHMARK.md`,
"Valid gold"); a value that fails becomes *uncertain* and counts neither way.

- **Checksums.** Generated values mostly fail their own checksum. Gretel: 1,046 of 1,175 ABA
  routing numbers, 438 of 1,009 cards, 312 of 1,527 IBANs, 255 of 1,117 SSNs. Nemotron: 7,511 of
  8,354 ABA numbers, 8,381 of 12,867 cards. Counted as missed, they made a rule look broken that
  was right.
- **Placeholders and reserved values.** Gretel's phones include `(123) 456-7890`, `(800) 123-4567`
  and `555-555-5555`; e-mail labels include reserved domains (example.com), which maisecrets leaves
  alone on purpose. Every Mendeley e-mail address is reserved, so e-mail is out of scope there.
- **Label errors.** A span with nothing of its type in it (`[Phone Number]`, a phrase such as
  "adresse e-mail professionnelle") is negative, not a missed value.
- **Spans wider than the value.** Every Mendeley card label covers a card block (holder, expiry,
  CVC): it is trimmed to the number. Trimming must never cut a group off a fake value: cutting
  until a checksum passes turned fake IBANs and cards into "valid" fragments no detector reports
  (Nemotron's card recall on valid gold went from 32.8% to 95.7% once the cut rule was fixed).
- **Wrong types.** Nemotron writes some account numbers as IBANs (`FR76 3000 …`); a valid one is
  scored as an IBAN.
- **Broken offsets.** Mendeley's texts carry mojibake that shifted 8% of the offsets; the adapter
  repairs the text before it places a span.
- **Chunked records.** A dataset that cuts long texts into records can start a record in the middle
  of a value it left unlabelled; the bench marks such a record's first token uncertain.

After cleaning, e-mail and IP recall on valid values is near 100% on Nemotron, and the real gaps
show: phone numbers, and cards and secrets in structured formats (CSV, FIX, XML fields).

## Porting notes

- Upstream supports Python 3.9 (stock macOS); the fork requires 3.12. A port must avoid 3.10+
  syntax (`match`, `X | Y` in runtime annotations) and run upstream's suite under 3.9.
- Each change above has its tests in the same commit (test first); `scripts/replay_can_fail.py`
  beliefs exist for the guarded ones.
- The bench itself (`bench/`, a separate uv project, developer-only) can come along so upstream can
  judge its own changes the same way; it never touches the plugin's release.
